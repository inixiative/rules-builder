# 0.33: editors for computation and evaluation, composed

Status: plan, revised after a duplication audit and an adversarial review (2026-11-18). Not built.

## Why

Zealot's derived enrichments are an ordered list of cases, each a condition and a computed value, with a
default. Aron (2026-11-18): "we are missing the thing to build... the derived enrichment frontend. That is
why I'm trying to get the categorized builder, the value picker, and the evaluation picker." And: "Some of
them are computation. Some of them are evaluation... we would probably want to be able to support the
primitives for composing those in the rules builder."

So the builder gets one editor per json-rules primitive, nested wherever json-rules' grammar nests them:
a condition (evaluation, `check`), a value expression (computation, `evaluateValue`), and a categorization
(`categorize`), whose cases are a condition plus a value expression. Kingdom's Signet issuing (FE-008) needs
the same pieces plus an entitlement editor.

## The editors

Composition is by pure root builders that take one `commit`, as `buildActionRoot` already embeds
`buildRoot`. Hooks are thin wrappers over them, since one hook per case can't nest.

1. **Value expressions** (`buildValueExpressionRoot`, `useValueExpressionBuilder`): a literal (an object
   emitted as `{ value }`), a source (the same value-source control conditions use, `{ value | path | bind }`
   plus offset), an aggregate (the condition builder's aggregate node without operator and threshold, plus
   `coerceType`, `caseInsensitive`), if / then / else (its `if` is the condition builder), a list (no list
   inside a list; an `if` without `else` adds nothing). Types from `inferValueType`, issues from
   `describeValue`. Paths from `lensScopeSurface`: values for paths, loops and scalar lists for aggregates.
2. **Categorizations** (`buildCategorizationRoot`, `useCategorizationBuilder`): ordered cases, each a
   condition root and a value root; add, remove, reorder; `match`; `default`. Issues from
   `describeCategorization`. A preview takes the caller's evaluator (Zealot widens dates and sets engine
   globals), so it never disagrees with production.
3. **Entitlement grants** (name to be set by what it edits: actions, `where`, lens):
   - actions: a caller-built operation tree (signet's `OperationNode[]`) and a caller predicate for what may
     be offered. No `*` or `.*` arithmetic and no ceiling computation here;
   - `where`: the added conditions only, under the positive gate, over the caller's where lens; the held
     conditions shown read-only; the caller composes with permissions' `delegatedWhere`;
   - lens: one parent-less narrowing over the composed held chain, checked by a caller `validateLens`
     (Kingdom wraps signet's `composeGrantLensChain`). The lens UI lands first in the example app, a
     provider's operations and events beside the generated lens.
4. **Permissions**: `self` gone, the list arm, rule leaves in the caller-passed rule lens, list arms only
   over declared `down` lists, the positive gate on `{ rule }` leaves.

Coercion comes from the lens and is already in json-rules: the condition editor runs `coerceRule` on emit (it does today, `useRuleBuilder.ts:120`) and the value editor runs `coerceValue` on emit the same way. A literal has no lens field behind it, so json-rules 4.2 takes `{ value, coerceType }` (FEAT-008), honoured by `evaluateValue` and `categorize` as `check()` honours a rule's `coerceType`. The value editor stamps it from the caller's expected kind (`acceptsType`, Zealot's map column); nothing guesses it from a neighbouring branch (Aron 11-18: "why dont we just respect in the normal call like check").

The actor is offered as untyped Json (`__actor`) until the actor bridge lands in permissions (TRACKING: "Actor bridge"), which turns `__actor.<kind>.*` into checked paths with no change here beyond reading the lens permissions exports.

Caller options every editor takes: `bindings: false` (Zealot refuses binds), allowed value shapes, and
`acceptsType(ValueType)` (Zealot's map column kinds). Engine globals (Zealot's clock floor) are the
caller's, set process-wide.
