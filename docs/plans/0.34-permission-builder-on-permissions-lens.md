# The permission builder reads permissions' own lens

Status: plan (2026-11-19), for adversarial review before building. Part of 0.34.

## Problem

`usePermissionBuilder`, `buildActionRoot` and the permission side of `useTransitionBuilder` author
rules in views rules-builder builds itself (`src/permissions/rawResources.ts`): `rawView` over the
maps (every column, every relation at the model defaults), `__actor` added as Json to every model,
and its own parse of `/// @permissions(down: [...])`. permissions judges the same rules in a
different lens (`permissions/src/core/lens.ts`): every followed to-one chain that never enters a
model twice (depth 20), `__actor` only on the row a `{ rule }` is read on, never in a `where`, and
under a list item only the declared `down` paths. So the builder offers rules `validateSchema`
refuses: a path back to a model, reads under an undeclared list, `org.__actor.x`. That is parallel
machinery (CLAUDE.md, "Look for the thing already doing it").

## Change

1. **permissions #37** (open, for Aron): exports `lensesAtRow(map, resource)` and
   `lensesAtListItem(map, resource, field)` (`LensesAtRow`: `lens`, `rule`, `resource`, `under`).
   `validateSchema`'s list arm uses `lensesAtListItem`.
2. **A `@inixiative/rules-builder/permissions` entry** holds `usePermissionBuilder`,
   `buildActionRoot`, `useActionRuleBuilder`, the action tree helpers and `useTransitionBuilder`.
   It imports permissions at runtime (peer, required for this entry only); the main entry never
   imports permissions, so Zealot (json-rules only) is unaffected.
3. **The input is permissions' `SchemaMap`** (`{ resources, fieldMap, polymorphism }`), the same
   object `createRebacCheck(map)` takes. A bare field-map `FieldMap` is not enough: the lens needs
   `resources` (resource name → model) and `polymorphism` (the kinds a polymorphic relation
   admits). Resources are permissions' resource names (`org`, `member`), not `map:model`.
4. **Per node:**
   - `{ rule }` leaf: authored in `createView(lensesAtRow(map, resource).rule)`.
   - list arm: offered over each to-many field of the resource for which `lensesAtListItem` is
     non-null; its `condition` is built at the item, with `rule` leaves in the item's `rule` lens.
   - `{ rel }` hop: segments offered from the to-one relations the resource's lens spells at the
     path walked so far (`viewAt`), plus `schema.bridges` hops from the resource; the target
     resource is the model's resource in `map.resources`. Under a list item: no bridge, no second
     list (as `validateSchema`).
   - Every node also shows `validateSchema`'s issues at its path, so the builder never disagrees
     with permissions even where its offering is coarser.
5. **Deleted:** `src/permissions/rawResources.ts` (`rawResourceViews`, `declaredListRelations`,
   `splitResource`, `ACTOR_FIELD`), the `resourceView` / `listRelations` options.
6. **Transitions:** a transition side's `permission` uses the same lenses. Its `predicate` (a
   json-rules condition on the record) keeps `rawView` unless transitions judges it in a lens of
   its own, to be checked (transitions 0.8 depends on permissions ^0.24).

## The actor

`__actor` stays untyped Json on the rule lens until the actor bridge (TRACKING "Actor bridge").
Aron 11-19 on the bridge's open questions: slot names are the app's model names (`apiToken` in
Zealot, `token` in template); related rows: probably reachable through relation checks instead,
to be checked. Today template fetches the token with user, organization, organizationUser, space,
spaceUser (with entitlements) and the user with organizationUsers, organizations, spaceUsers,
spaces, but the actor a rule reads is `pickColumns` minus sensitive fields
(`template/packages/permissions/src/actorFromRecordOmittingSensitiveFields.ts`). No rule in
template's schema reads `__actor` today.

## Tests

- A path back to a model, an undeclared list, `org.__actor.x` are not offered; a rule using them
  shows `validateSchema`'s issue.
- A declared list arm offers only its `down` paths at the item.
- A bridge hop lands on the far resource and offers its actions.
- Consumers: none outside the example app (grep of template, Kingdom, Zealot), so no migration.
